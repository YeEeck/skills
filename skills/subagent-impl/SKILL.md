# 子代理串行实现

你负责编排；执行交给子代理。每张票一个子代理，**串行**：上一张票经验证的结果，是下一张票的**前提**。

顺序已经由票据定好——`to-tickets` 按依赖优先编号，每张票都声明了自己的 **Blocked by** 边。照这个顺序走，不要重新规划。

## 1. 载入票据集

找到用户指向的票据——本地票据文件（如 `.scratch/<feature-slug>/issues/`）或 tracker issues，取决于 `to-tickets` 发布到了哪里——并全部读一遍。同时记下当前 HEAD 为**基准 revision**：第 3 步终审从它开始审。

完成标志：手中握有按执行顺序排好的完整清单——一张票只有在其所有阻塞项都经验证后才算就绪。

## 2. 一轮一张，串行推进

即使同时有多张票就绪，也一轮只跑一张——串行是契约：它保证每个前提在被依赖之前已经过验证，也让子代理之间互不踩对方的工作树。

对每张票：

1. **派发**一个子代理（用当前环境提供的子代理机制），prompt 必须**自包含**——它看不到本次会话。要包含：票据正文原样贴入；代码位置；前提——先前各票改了什么、如何验证通过的；验收标准即契约；并要求它**调用 `implement` 技能来实施本票**（`implement` 是 user-invoked，不会自发触发——必须在 prompt 里点名，按其环境支持的方式：`/implement` 调用，或指示它先加载 `implement` 技能再动工）。实现纪律以 `implement` 为准，不在 prompt 里重写。最后要求它如实报告自己改了什么。
2. **等待**其结束，才派发下一张票。
3. **亲自验证**每一条验收标准——读 diff、跑测试或 typecheck。不通过，就把失败的标准当作修正意见写进 prompt，重派同一张票。
4. **勾选并记录**——在票据里（文件勾选项或 tracker）把验证通过的标准勾掉，并为后面的票记下这轮改了什么、定了什么决策。

完成标志：所有票据验证通过、验收标准全部勾选。

## 3. 全量终审：code-review

所有票勾选完毕，**不等于**这批活干完了——单票验收只保证每张票自己的标准勾得上，票与票之间累积的规范漂移、对 spec 的误读，要到全量 diff 才现形。

这时调用 `code-review` 技能，从基准 revision 起审全部改动：Standards 轴对照仓库编码规范，Spec 轴对照这批票据及其 spec。它派的是只读评审、不动工作树，与串行契约不冲突。

处置每条发现——**每条都要有着落**：

- 违背某张票的验收标准 → 重开该票，回第 2 步补一轮，补完连同受影响的后续票重新验证。
- 票据之外的问题 → 记入第 4 步的遗留清单交给用户定夺，修不修由用户说了算。

完成标志：每条发现要么已修复并复验，要么已进遗留清单。

## 4. 汇报

逐票汇报：落地了什么、验证结果、是否发生过重派；终审的发现与各自处置；以及遗留的问题。
